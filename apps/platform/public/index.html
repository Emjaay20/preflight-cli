2. Structured Scanner Agents & Policy Packs (cws-2026.1 & node-client-2026.1)

The scanner evaluates two built-in rule packs against your extension artifact and claims.json:

ControlPackSeverityWhat It Verifies
CWS-01cws-2026.1blockermanifest_version must be 3.
CWS-02cws-2026.1highEvery file referenced in manifest.json exists in the archive.
CWS-03 / CWS-07cws-2026.1highBlocks broad host patterns (*://*/*, <all_urls>) and cleartext http:// or ws:// endpoints.
CWS-05 / CWS-06cws-2026.1highRequires an https:// privacy URL and a declared purpose for every manifest permission.
CWS-08cws-2026.1blockerBlocks eval(), new Function(), remote script imports, and unsafe-eval CSP.
NODE-01 / NODE-02node-client-2026.1blockerEvery manifest host permission and JS network destination must match claims.allowed_hosts.
NODE-03 / NODE-04node-client-2026.1blocker/highNetworked extensions must enforce an explicit consent check and a runtime kill switch.
NODE-06 / NODE-07node-client-2026.1highBlocks private/loopback network targets (127.0.0.1, 192.168.x.x) and third-party update_url hosts.
3. Account Types (Organization vs. Individual) & RBAC Roles

Preflight isolates every workspace at the database, API key, and filesystem levels:

  • Organizations (accountType: "organization"): Designed for teams. Admins can invite team members (POST /v1/members/invite) and assign each person a dedicated pf_live_… key with role admin, reviewer, or ci.
  • Individuals (accountType: "individual"): Designed for solo developers. Creates a personal workspace with zero team-management overhead while still supporting additional personal CLI/CI keys.
  • Separation of Duties (ADR-0003): Keys with the ci role can upload builds and poll verdicts, but are cryptographically blocked from signing off human release decisions.
